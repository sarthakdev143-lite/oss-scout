### sqlite-jdbc#1509 CI failure: root cause and reply
All 28 red jobs are the same crash: `Aborted (core dumped)`, exit 134, in `org.sqlite.ExtensionTest`.
`mvn test` in CI runs against the prebuilt `libsqlitejdbc.so` files committed under
`src/main/resources/org/sqlite/native/`. They predate the C fix, so the new `rightstrNegativeLength`
test calls the old `rightstr` and kills the JVM. Same failure on other open PRs touching
`extension-functions.c` (#1520). Upstream rebuilds natives in a separate "chore: update native libraries"
commit after C fixes (e.g. 033f6c34 on 2026-10-29, same day 87444aed merged).

Verified in a fresh clone `/tmp/sqlite-jdbc-2026-11-26` (master merged with the PR branch), docker
`maven:3.9-eclipse-temurin-21`:
- `mvn -Dtest=ExtensionTest test` with the committed native: JVM crash, exit 134.
- after `make native` from the merged tree, same command: `ExtensionTest` tests=8 failures=0 errors=0.

Posted a factual reply on the PR with that evidence:
https://github.com/xerial/sqlite-jdbc/pull/1509#issuecomment-7187823004
No code change is correct: pushing rebuilt binaries from a contributor branch is not how upstream works.
